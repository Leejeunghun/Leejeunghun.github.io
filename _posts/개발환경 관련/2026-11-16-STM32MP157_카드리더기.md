[지난 글]({ post_url 2026-11-13-sc6-hmi-dwin-and-rfid-reader })에서 카드 리더 프로그램(sc6-rfid)과 화면 프로그램(sc6-hmi)을 만들었다. 하지만 EVerest는 여전히 고정 카드 번호로 꽂자마자 자동 인증하고 있었다. 오늘(11/16)은 이 자동 인증을 카드 리더로 바꾸고, 사용자가 처음 보는 화면을 인증 화면으로 만들었다.

| 일 | 결과 |
|---|---|
| 카드 인증 연결 | 자동 인증 → 카드 리더(`rfid_1`). 미등록 카드 거절, 등록 카드 승인 → 거래 시작 |
| 인증 화면 (sc6-hmi r0.10) | 메인 버튼 → "카드를 접촉해 주세요" → 승인되면 준비 화면 |
| 카드로 충전 정지 | EVerest 기본 동작이지만 **보류**. 정지는 중지 버튼만 |
| 보드 한 바퀴 | 인증 → 충전 → 중지 → 결과 → 분리 안내 → 메인, 2회 정상 |

## 1. 자동 인증을 카드 리더로 바꾸다

### 1-1. EVerest 구성은 모듈 하나 바꾸기

EVerest Auth 모듈은 "누가 카드 번호를 주는가(token_provider)"를 구성 파일에서 연결한다. 지금까지는 시험용 가짜 공급자(`DummyTokenProvider`)가 꽂는 순간 고정 번호를 줬다. 이것을 바깥 프로그램용 공개 API 모듈로 바꿨다.

```yaml
rfid_1:
  module: auth_token_provider_API   # sc6-rfid 가 MQTT 로 카드 번호를 넣는 곳
auth:
  connections:
    token_provider:
      - module_id: rfid_1
      - module_id: ocpp             # 서버가 원격으로 시작할 때
```

가짜 공급자는 지우지 않고 주석으로 남겨, 리더 없이 시험할 때 되돌릴 수 있게 했다. 이미지의 everest-core에 이 API 모듈이 실제로 들어 있는지 deb 안을 먼저 확인했다.

### 1-2. 첫 카드는 Invalid

보드에서 sc6-rfid를 띄우고 카드를 대자 EVerest는 번호를 받았다. 하지만 OCPP 서버(SteVe)는 `Invalid`로 답했다. 프로그램 문제가 아니라 **서버에 등록하지 않은 카드**였다. SteVe의 OCPP 태그에 시험 카드 번호를 등록하자 바로 `Accepted`가 오고 StartTransaction이 나갔다. 일부러 등록하지 않은 번호도 하나 남겨 두고, 그 카드로는 여전히 거절되는 것을 확인했다.

### 1-3. 카드 먼저든 꽂기 먼저든

로그로 두 순서를 모두 확인했다. 어느 순서든 **인증과 연결이 둘 다 갖춰져야** 거래가 시작된다.

```text
카드 먼저:  카드 → SessionStarted, Authorized → (꽂음) AuthRequired, TransactionStarted → (C) ChargingStarted
꽂기 먼저:  (꽂음) SessionStarted, AuthRequired → 카드 → Authorized, TransactionStarted → (C) ChargingStarted
```

카드 없이 꽂고 지그를 C로 바꿔도 K1은 붙지 않았다. 자동 인증 시절에는 꽂기만 하면 충전됐으니, 이제야 "카드를 대야 충전되는" 충전기가 됐다.

## 2. 인증 화면 (AUTH)

### 2-1. 사용자가 처음 보는 화면

화면 흐름의 시작을 바꿨다. 메인 화면에서 버튼을 누르면 "카드를 접촉해 주세요" 화면과 음성으로 간다. 카드가 승인되면 준비 화면으로 넘어간다. 카드 없이 먼저 꽂은 경우에도 EVerest가 `AuthRequired`를 보내므로 같은 인증 화면으로 간다.

```text
MAIN ─버튼─▶ AUTH ─Authorized─▶ PREPARE ─ChargingStarted─▶ CHARGING
              ▲
     (카드 없이 꽂음: AuthRequired)
```

화면 번호는 지난번처럼 코드에 넣지 않고 설정 파일에 둔다.

```ini
PAGE_AUTH=2
SOUND_AUTH=2            # "카드리더기에 회원카드를 접촉해주세요"
BUTTON_STATE_1=AUTH     # 메인 버튼 1 -> AUTH 상태
```

### 2-2. 이미 승인된 카드에 "인증하세요"를 다시 띄우지 않기

카드를 먼저 대고 나중에 꽂으면, EVerest는 꽂는 순간에도 `AuthRequired`를 보낸다. 이것을 그대로 따르면 준비 화면이 인증 화면으로 잠깐 되돌아가고 안내 음성이 한 번 더 난다. 그래서 sc6-hmi가 승인 여부(`Authorized`가 왔는지)를 기억해 두고, 이미 승인됐으면 `AuthRequired`를 무시한다.

시간 초과도 한 군데 더 정했다. **꽂지 않은** 인증 화면은 60초 뒤 메인으로 돌아간다. **꽂혀 있는** 인증 화면은 돌아가지 않는다. 꽂힌 채 메인 화면이 되면 안 되고, 기다림은 EVerest의 인증 대기 시간에 맡긴다.

### 2-3. 설정 한 줄이 세 번 걸렸다

버튼을 인증 화면에 연결하는 줄에서 세 번 막혔다.

| 적은 값 | 결과 |
|---|---|
| `BUTTON_STATE_1=6` | "모르는 상태 이름"으로 무시 → 옛 줄 `BUTTON_PAGE_1=6`이 대신 동작 |
| `BUTTON_STATE_1=1` | 역시 무시 |
| `BUTTON_STATE_1=AUTH` | 시작 로그에 `버튼 1 -> 상태 AUTH` |

`BUTTON_PAGE_`는 값이 화면 **번호**이고, `BUTTON_STATE_`는 값이 상태 **이름**이다. 이름이 비슷한 두 키의 값 종류가 다르니 헷갈릴 만하다. 다행히 프로그램이 설정을 읽을 때 무시한 줄을 로그에 남겨서, 올리기 전에 파일만 보고 잡을 수 있었다.

## 3. 충전이 카드로 멈췄다

### 3-1. 로그가 말해 준 것

인증 화면 첫 시험에서 충전 → 정지 → 결과까지 잘 갔다. 그런데 로그에 중지 버튼(버튼 2)이 없었다. 대신 정지 직전에 이 줄이 있었다.

```text
13:34:28.975 sc6-rfid: 카드 티머니 1122334455667788 -> EVerest     ← 인증
13:34:36.604 sc6-rfid: 카드 티머니 1122334455667788 -> EVerest     ← 같은 카드 다시
13:34:36.721 sc6-hmi:  ← session_event StoppingCharging
```

충전 중에 **같은 카드가 다시 오면 충전을 끝내는 것**은 EVerest Auth의 기본 동작이다. 시작한 카드로 끝내는 충전기도 흔하다. 하지만 지금 화면 흐름에서는 카드를 대는 곳이 인증 화면뿐이고, 충전 중에 실수로 카드를 대면 충전이 끊길 수 있다. 그래서 **카드로 멈추는 기능은 보류**하고 정지는 화면의 중지 버튼으로만 하기로 했다.

### 3-2. EVerest를 고치지 않고 카드 리더 쪽에서

EVerest Auth 설정에는 "거래 중 카드로 정지 안 함" 같은 스위치가 없다. EVerest를 고치는 대신, 카드 번호를 넘겨주는 sc6-rfid가 **거래 중에는 넘기지 않게** 했다.

- 거래 여부는 sc6-hmi와 같은 공개 API의 `e2m/session_event`로 안다. `TransactionStarted`부터 `TransactionFinished`(또는 `SessionFinished`)까지가 거래 중이다.
- 거래 중에 댄 카드는 로그만 남기고 버린다.
- 설정 `STOP_BY_CARD=1`로 바꾸면 원래 동작으로 돌아간다.

PC 시험용 MQTT 대체 파일에는 그동안 "보내기"만 있었다. 이번에 "받기"도 넣었다. 파일에 토픽과 내용을 한 줄 쓰면 받은 메시지로 넘겨주는 방식이다. 이것으로 거래 시작과 끝을 흉내 내 두 설정을 모두 시험했다.

| | 거래 전 카드 | 거래 중 카드 | 거래 끝난 뒤 카드 |
|---|---|---|---|
| `STOP_BY_CARD=0` (지금) | 보냄 | **버림** | 보냄 |
| `STOP_BY_CARD=1` | 보냄 | 보냄 (정지) | 보냄 |

한계도 있다. sc6-rfid를 **충전 도중에** 새로 띄우면 지금이 거래 중인지 모른다. 그 충전 하나는 카드로 멈출 수 있다. 서비스로 부팅 때 뜨면 문제가 없고, 손으로 시험할 때는 충전 전에 띄운다.

## 4. 시작부터 분리까지 한 바퀴

새 sc6-rfid로 두 번 돌렸다. 두 번 모두 같았다.

| 시각 (1회차) | 일어난 일 | 화면 |
|---|---|---|
| 16:43:24 | 메인 버튼 1 | MAIN → AUTH |
| 16:43:40 | 등록 카드 → `Authorized` | → PREPARE |
| 16:43:43 | 꽂음(B), `AuthRequired`는 무시, `TransactionStarted` | PREPARE 그대로 |
| 16:43:46 | C, `ChargingStarted`, K1 ON | → CHARGING |
| 16:43:53 | **중지 버튼** → `stop_transaction` 응답 `true` (14 ms) | → STOPPING |
| 16:43:59 | K1 OFF, `TransactionFinished` (6.2초 뒤) | → FINISHED |
| 16:44:10 | **완료 확인 버튼** | → UNPLUG (커넥터 분리 안내) |
| 16:44:12 | 분리(A), `SessionFinished` | → MAIN |

지난번에 남겨 둔 "결과 → 분리 안내 → 메인" 흐름도 이번에 처음 확인됐다.

정지 버튼을 누른 뒤 K1이 떨어지기까지는 약 6초가 걸린다. 차가 C에서 B로 내려 주기를 EVerest가 기다리다가 강제로 끊기 때문이다(지그는 C 그대로라서). 그 6초 동안 화면은 충전 중 화면 그대로라, 정지 중 화면이나 안내 음성을 따로 둘지 정해야 한다.

## 5. 정리

### 커밋

```text
meta-sc6  19a9dfe  sc6-everest-config: 인증 토큰을 카드 리더(rfid_1)에서
meta-sc6  abb591c  sc6-hmi: 인증 화면(AUTH) 상태 추가
meta-sc6  c1f2110  sc6-rfid: 거래 중에 댄 카드는 EVerest 에 보내지 않음 (카드로 정지 보류)
sc6-work  ff5a82c  보드 시험: sc6-hmi + sc6-rfid 함께 실행, 로그·SteVe 확인 스크립트 (11/16)
```

### 배운 것

1. **Invalid는 프로그램 오류가 아닐 수 있다.** 서버가 모르는 카드면 모든 것이 정상이어도 거절된다. 먼저 서버의 등록 목록을 본다.
2. **같은 이벤트도 앞선 일에 따라 뜻이 다르다.** `AuthRequired`는 카드 없이 꽂았을 때는 "인증하세요"지만, 이미 승인된 뒤라면 무시해야 할 신호다.
3. **로그는 의도하지 않은 경로도 보여 준다.** 화면만 보면 "정지 잘 됨"이었지만, 로그에는 버튼이 없고 카드가 있었다.
4. **바꿀 수 없는 기본 동작은 입구에서 거른다.** EVerest를 고치지 않고 카드 번호를 넘기는 쪽에서 거래 중 카드를 버렸다. 설정 하나로 되돌릴 수도 있다.

### 남은 것

| 항목 | 내용 |
|---|---|
| 보드 시험 | 충전 중 카드 대기(버려지는지), 인증 화면 60초 시간 초과, 인증 화면에서 미등록 카드 |
| 화면 | 정지 중 6초 동안의 화면·음성, 거절된 카드 안내 (`auth_consumer_API`의 인증 결과로) |
| 카드 | 실제 카드의 ID 형식 확인 |
| 보류 | 분리할 때 카드로 인증하는 기능 |
| 이미지 | sc6-hmi, sc6-rfid를 이미지에 넣고 SD 다시 굽기 |
