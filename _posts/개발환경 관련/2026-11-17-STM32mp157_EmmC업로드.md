지난 글(11/16, 카드 인증과 인증 화면)까지 모든 작업은 SD 카드로 부팅해서 했다. 하지만 제품은 SD 카드 없이 모듈 안의 eMMC로 부팅한다. 오늘(11/17)은 지금까지 SD에서 확인한 것을 eMMC로 옮겼다.

| 일 | 결과 |
|---|---|
| eMMC 배치 | ST 배치표 기준, rootfs 1.5GiB. 4GB 모듈에도 들어감 |
| 방법 1: SD에서 직접 쓰기 | `write-emmc.sh` → eMMC 부팅, 충전 한 바퀴 정상 |
| 방법 2: CubeProgrammer USB | TF-A·U-Boot에 USB 설정 추가 → PC에서 eMMC 전체 굽기 성공 |
| 보드 설정 복원 | `settings` 모드로 WiFi, 서버 CA, OCPP 사용자 설정만 복사 |
| 새 보드 (4GB eMMC) | CubeProgrammer → 설정 복원 → eMMC 부팅, WiFi 연결 |

## 1. 무엇을 어디에 둘까

### 1-1. 공장 상태부터 백업

이 보드의 eMMC에는 MYiR 출하 이미지가 들어 있었다. 지우기 전에 SD로 부팅해서 통째로 떠 두었다.

- 부트 영역 `boot0`, `boot1` (각 4MB, 출하 TF-A가 들어 있음)
- 사용자 영역 전체 (7.3GiB, 압축하면 105MB)
- 원래 파티션 표 (`sfdisk -d`)

빌드 PC에 두고 압축 해제 크기와 md5까지 확인한 뒤에 다음으로 넘어갔다. 문제가 생기면 이것으로 출하 상태로 돌린다.

### 1-2. 배치표는 ST 것을 그대로

ST의 Yocto는 부팅 장치마다 배치표(`FlashLayout_*.tsv`)를 만든다. 머신 설정에 `emmc`를 추가하면 eMMC용 TF-A, FIP, 배치표가 SD용과 함께 나온다.

```text
boot0/boot1   TF-A (fsbl1, fsbl2)
p1, p2        metadata1, metadata2   (어느 FIP 로 부팅할지)
p3, p4        fip-a, fip-b           (OP-TEE + U-Boot, 4MB 씩)
p5            u-boot-env
p6            bootfs     64MB   커널, DTB, extlinux
p7            vendorfs   16MB
p8            rootfs     1.5GiB
p9            userfs     나머지  (/usr/local)
```

ST 기본 rootfs는 3GiB다. 이 보드의 eMMC는 7.3GiB라 문제가 없지만, 제품 모듈은 4GB라고 들었다. 4GB 모듈의 실제 크기는 약 3.6GiB이니 rootfs를 1.5GiB로 줄였다. 지금 rootfs 내용은 약 210MB라 넉넉하다. MYiR 출하 이미지도 rootfs가 1.5GB였다.

### 1-3. 크기 변수가 안 먹었다

처음에는 `STM32MP_ROOTFS_SIZE:emmc`를 바꿨다. 빌드는 됐지만 배치표의 rootfs는 여전히 3GiB였다. 이 변수는 파일시스템 이미지 크기에만 쓰이고, 배치표는 다른 곳의 기본 크기를 읽는다. 배치표 전용 변수로 바꾸자 userfs 시작 위치가 1.5GiB 뒤로 당겨진 것이 배치표에 보였다.

```bitbake
FLASHLAYOUT_PARTITION_SIZE:opteemin:emmc:rootfs = "1572864"   # KiB
```

**빌드가 성공했다고 끝이 아니라 결과물(배치표)을 열어 봐야 한다**는 것을 다시 배웠다.

### 1-4. DTS 변경은 빌드가 모른다

TF-A와 U-Boot의 DTS에 eMMC(sdmmc2, 8비트)를 넣었다. 그런데 이 DTS는 레이어 밖 경로에 있어서, 고쳐도 bitbake가 바뀐 줄 모르고 이전 결과를 그대로 썼다. eMMC 작업 동안에는 TF-A, U-Boot, FIP을 매번 지우고(`cleansstate`) 다시 빌드했다.

## 2. 방법 1: SD로 부팅해서 eMMC 직접 쓰기

### 2-1. 스크립트 하나로

먼저 장비 없이 할 수 있는 방법부터 했다. SD로 부팅한 리눅스에서 eMMC는 `/dev/mmcblk1`로 보인다. `write-emmc.sh`가 하는 일은 이렇다.

1. 지금 SD로 부팅했는지, eMMC가 마운트돼 있지 않은지, 받은 파일의 md5가 맞는지 확인
2. GPT 작성: 위치, 종류, 고유번호를 ST 배치표와 같게
3. metadata, FIP, 파일시스템 이미지를 각 파티션에 쓰기
4. TF-A를 `boot0`, `boot1`에 쓰고 다시 읽어 비교
5. eMMC가 부트 영역으로 부팅하게 설정되어 있는지 확인 (이미 되어 있으면 건드리지 않음)
6. 파일시스템을 파티션 크기로 늘리기
7. SD에 있는 보드 설정을 eMMC rootfs로 복사

고유번호를 ST와 같게 맞추는 이유는 부팅 단계마다 이것으로 다음 것을 찾기 때문이다. TF-A는 metadata에 적힌 FIP 고유번호로 FIP을 찾고, 커널은 rootfs의 PARTUUID로 루트를 찾는다. SD와 eMMC의 rootfs PARTUUID는 서로 달라서, 둘 다 꽂혀 있어도 헷갈리지 않는다.

7번이 필요한 이유는 이미지에 들어가면 안 되는 것들이 있어서다. WiFi 비밀번호, 서버 CA, OCPP 서버 비밀번호는 보드에서 넣었다. 스크립트는 이 파일들을 복사한 뒤 **권한만** 출력하고 내용은 출력하지 않는다.

### 2-2. 세 번 걸렸다

| 증상 | 원인 | 고침 |
|---|---|---|
| "SD로 부팅한 상태가 아님"으로 중단 | 루트가 `/dev/disk/by-partuuid/...`로 보여서 `mmcblk0`과 비교가 안 됨 | `readlink -f`로 실제 장치로 바꿔 비교 |
| 확인 `YES`가 입력되지 않음 | 터미널에 따라 입력을 못 받음 | `bash write-emmc.sh YES`처럼 인자로도 받음 |
| `/usr/local`이 136K, 100% | 첫 부팅 때 rootfs는 늘려 주지만 userfs는 안 늘려 줌 | 스크립트가 `resize2fs`로 직접 늘림 |

### 2-3. eMMC 첫 부팅

스위치(SW1)를 eMMC로 바꾸고 SD를 뺐다. 이 보드의 부팅 스위치는 이렇다.

| 부팅 장치 | SW1 (1, 2, 3) |
|---|---|
| SD 카드 | ON, OFF, ON |
| eMMC | OFF, ON, OFF |
| USB (CubeProgrammer) | OFF, OFF, OFF |

서비스 8개가 모두 떴고, OCPP TLS로 SteVe에 붙어 BootNotification이 들어왔다. 11/16에 SD에서 했던 카드 인증 → 충전 → 중지 → 분리 한 바퀴도 eMMC에서 그대로 됐다.

## 3. 방법 2: STM32CubeProgrammer USB

### 3-1. 왜 따로 하나

방법 1은 SD 카드와 SSH가 필요하다. 생산할 때는 빈 보드를 USB로 PC에 꽂고 한 번에 굽는 방법이 맞다. ST가 이 용도로 만든 것이 CubeProgrammer의 USB(DFU) 굽기다. 이것은 4단계로 진행된다.

```text
1. 스위치 USB → 칩 안의 ROM 이 USB 장치로 붙음
2. PC 가 TF-A(USB 판)를 RAM 에 올림 (0x01)
3. PC 가 FIP(OP-TEE + U-Boot)를 올림 (0x03) → U-Boot 가 USB 로 다시 붙음
4. U-Boot 가 받은 파일을 배치표대로 eMMC 에 씀
```

2단계부터는 **우리 TF-A와 U-Boot가 USB를 다뤄야** 한다. SD 부팅만 할 때는 USB를 쓰지 않아서 DTS에 USB 설정이 없었다.

### 3-2. 연결부터 안 됐다

처음에는 CubeProgrammer가 연결 실패를 냈고, PC 장치 관리자에는 "알 수 없는 USB 장치(장치 설명자 요청 실패)"가 보였다. 로그의 `UR connection mode`가 단서였다. 이것은 디버거(ST-LINK) 연결 방식이고, CubeProgrammer 연결 종류가 ST-LINK로 되어 있었다. USB로 바꾸자 ROM이 고속(HS)으로 붙었다.

### 3-3. TF-A에 USB 넣기

TF-A DTS에 USB 장치(OTG HS)와 USB PHY를 켰다. 이 보드의 USB-C(J5)는 PHY 1번 포트에 연결돼 있다. 또 STM32MP15의 USB PHY는 3.3V 전원 공급원을 DT에서 찾는다. SC6는 이 전압을 보드에서 항상 주고 있으니 고정 3.3V 레귤레이터로 적었다. TF-A 단계(0x01)는 이것으로 지나갔다.

### 3-4. U-Boot에서 멈췄다

FIP(0x03)까지 올라간 뒤 CubeProgrammer가 "Reconnecting the device ..."에서 더 나가지 않았다. PC에는 다시 "장치 설명자 요청 실패"가 보였다. U-Boot가 USB를 열었지만 PC와 대화를 시작하지 못한 것이다.

U-Boot의 USB 장치 드라이버(dwc2)는 VBUS가 들어왔는지 보고 연결됐다고 판단한다. SC6는 DK1 보드처럼 USB-C VBUS를 Type-C 칩(STUSB1600)이 다루고, MPU는 VBUS를 직접 보지 못한다. ST의 DK1용 U-Boot 설정에는 이럴 때 "연결된 것으로 간주하라"는 한 줄이 있었다.

```dts
&usbotg_hs {
	u-boot,force-b-session-valid;
};
```

SC6용 U-Boot 설정을 DK1 것에서 시작하면서, DK1에만 있는 LED와 버튼 설정을 지웠다. 그때 이 줄도 같이 빠졌던 것이다. 다시 넣고 U-Boot와 FIP만 다시 빌드했다. CubeProgrammer는 끝까지 갔다: ROM → TF-A USB → U-Boot USB → 파티션 9개.

`dr_mode = "peripheral"`도 넣었지만 이 판단에는 쓰이지 않는다. 드라이버 소스를 읽어서 확인했다.

### 3-5. 구운 뒤에는 설정만

CubeProgrammer로 구운 eMMC에는 **이미지만** 있다. WiFi, 서버 CA, OCPP 사용자 설정이 없어서 서버에 붙지 못한다. WiFi만 직접 넣는 방법도 있지만, 서버 연결까지 하려면 나머지도 필요하다. 그래서 `write-emmc.sh`에 `settings` 모드를 만들었다. SD로 한 번 부팅해서 실행하면 eMMC의 파티션과 이미지는 그대로 두고 7번(보드 설정 복사)만 한다.

```bash
bash emmc/write-emmc.sh settings
```

다시 eMMC로 부팅하자 USB 설정을 넣은 새 부트로더로도 정상 부팅했다. 서비스 8개가 active였고, OCPP는 시작 1초 만에 서버에 연결됐다.

여기서도 작은 것 두 개를 고쳤다.

- `settings`를 두 번 돌리면 이미지 기본값 사본(`sc6-bsp.image`)을 SD 값으로 덮어써서, 비교 결과가 "같음"으로 잘못 나왔다. 사본이 이미 있으면 그대로 두게 했다.
- CubeProgrammer 묶음을 만들 때 빌드 PC의 eMMC 폴더를 지우고 새로 만드는데, 따로 올려 둔 부팅 확인 스크립트까지 지워졌다. 묶음에 같이 넣게 했다.

## 4. 새 보드: 4GB eMMC

같은 방법을 새 보드에 그대로 했다. CubeProgrammer로 굽고, SD로 부팅해 `settings`를 실행하고, eMMC로 부팅했다.

이 보드의 eMMC는 **3728MiB, 4GB 모듈**이었다. 1.5GiB로 줄여 둔 rootfs가 그대로 들어갔고, userfs(`/usr/local`)는 약 2.0GiB가 됐다. 7.3GiB 보드에서는 5.7GiB였으니 userfs만 줄어든다.

그런데 IP가 잡히지 않았다. 로그를 나눠 보니 원인은 두 가지가 겹친 것이었다.

```text
17:13:53  Trying to associate with SSID ...
17:13:53  ASSOC-REJECT status_code=16          ← 공유기가 연결 요청에 제때 응답 안 함
17:14:04  ASSOC-REJECT status_code=16
17:14:31  CONNECTED - Key negotiation completed ← 세 번째에 연결
17:14:33  Gained IPv6LL                        ← 그런데 IPv4(DHCP) 기록이 없음
```

WiFi 칩(BCM43430)과 설정 파일은 정상이었다. 연결은 세 번째에 됐지만 IPv4 주소를 받지 못했다. `networkctl renew wlan0`으로 DHCP를 다시 요청하자 주소가 잡혔다. 새 보드는 WiFi MAC이 달라 공유기가 처음 보는 기기였다. 이런 일이 반복되면 공유기에서 MAC에 IP를 예약해 둘 생각이다.

두 보드는 같은 이미지라 충전기 ID가 둘 다 `SC6-0001`이다. 둘이 동시에 SteVe에 붙으면 서로를 끊으므로, 지금은 한 대씩만 켠다.

## 5. 정리

### 커밋

```text
meta-sc6  2276093  sc6-image: sc6-hmi, sc6-rfid 와 eMMC 도구(gptfdisk, mmc-utils) 추가
meta-sc6  bda972d  eMMC 부팅과 CubeProgrammer USB 굽기
sc6-work  3776c3c  eMMC 이전: SD 에서 eMMC 쓰기, CubeProgrammer 묶음, 부팅 확인 스크립트 (11/17)
```

### 배운 것

1. **빌드 결과물을 열어 본다.** rootfs 크기 변수는 빌드 오류 없이 무시됐다. 배치표를 열어 보고서야 알았다.
2. **다른 보드 설정에서 지운 줄이 무엇이었는지 기억한다.** DK1의 LED·버튼 설정을 지우면서 USB 판단 한 줄도 같이 빠졌다. USB를 안 쓸 때는 드러나지 않다가 CubeProgrammer에서 드러났다.
3. **이미지와 보드 설정을 나눈다.** 비밀번호와 인증서는 이미지에 넣지 않았다. 그래서 굽는 방법이 둘이어도 "설정 복사"는 같은 스크립트 하나로 된다.
4. **연결됐다고 IP가 있는 것은 아니다.** WiFi 연결, DHCP, IP를 나눠 봐야 어디서 멈췄는지 보인다.

### 남은 것

| 항목 | 내용 |
|---|---|
| 새 보드 | 부팅 확인 스크립트 실행 (서비스 8개, OCPP 연결), 충전 한 바퀴 |
| 생산 | 설정 복원까지 SD 없이 하는 방법 (CubeProgrammer로 설정 파티션을 같이 굽기 등) |
| 두 대 운영 | 보드마다 다른 충전기 ID와 SteVe 등록 |
| 보드 시험 (11/16에서) | 충전 중 카드 대기, 인증 화면 60초 시간 초과, 미등록 카드 |
| 전력 시험 | 실제 부하로 단계별 시험 |
| 로그 | 30초마다 나오는 `set_external_limits` 경고 확인 |
