SC6_0 보드 브링업을 시작한 지 6주가 지났다. 그동안 커널 DTS를 새로 쓰고, 커널 설정을 바꾸고, U-Boot을 다시 빌드하고, 보드에 서비스를 깔았다. 블로그 글은 문제 하나씩 따라가며 썼기 때문에 **"결국 무엇이 바뀌었나"** 를 한눈에 보기가 어려웠다.

이 글은 그 목록이다. 기억에 의존하지 않고, 수정 내역을 **실제 파일과 diff로 다시 확인**해서 정리했다.

## 0. 한눈에

| 구분 | 위치 | 종류 | 한 줄 요약 |
|---|---|---|---|
| 커널 DTS | `stm32mp157a-sc6-v1.dts` | **신규** | SC6_0 보드 정의 |
| 커널 DTS | `stm32mp157-sc6-pinctrl.dtsi` | **신규** | 벤더와 배선이 다른 핀 그룹 6개 |
| 커널 DTS | `arch/arm/boot/dts/Makefile` | 수정 (1줄) | 새 DTB를 빌드 목록에 등록 |
| 커널 설정 | `build/.config` | 수정 (2항목) | QCA7005 드라이버를 모듈로 활성화 |
| U-Boot DTS | `stm32mp157c-ya157c-512d-v2-u-boot.dtsi` | 수정 (31줄 추가) | LCD 관련 노드 3개 비활성화 |
| U-Boot 설정 | `build-trusted/.config` | 수정 (1항목 + 자동 의존) | 빌드 실패 해결용 |
| 보드 | `/boot/` | 추가·수정 | 새 DTB, 부팅 메뉴 |
| 보드 | `/lib/modules/` | 추가 | QCA 드라이버 모듈 2개 |
| 보드 | SD카드 SSBL 파티션 | 교체 | 새 U-Boot |
| 보드 | `/usr/local/`, `/etc/systemd/`, `/lib/firmware/` | 추가 | PLC 도구, 펌웨어 자동 적재 서비스 |

**벤더 원본 파일은 하나도 고치지 않았다.** 커널은 벤더 DTS를 `#include`해서 덮어쓰는 방식이고, U-Boot은 원래 있던 보드별 오버레이 파일(`-u-boot.dtsi`)에 덧붙이는 방식이다. 이게 어떻게 확인됐는지는 6절에 적었다.

## 1. 커널 소스

### 1-1. Makefile — 1줄

`arch/arm/boot/dts/Makefile` 1014번째 줄에 한 줄을 넣었다.

```makefile
	stm32mp157c-ya157c-lcd-v2.dtb \
	stm32mp157a-sc6-v1.dtb \            ← 추가
	stm32mp15xc-ya151c-t.dtb \
```

이게 없으면 `make stm32mp157a-sc6-v1.dtb`가 "규칙이 없다"며 거부한다.

### 1-2. stm32mp157-sc6-pinctrl.dtsi — 신규

**벤더 평가보드와 배선이 다른 핀만** 그룹으로 정의했다. 배선이 같은 것(콘솔, 블루투스, SPI1, I2C4, SD 등)은 벤더 그룹 이름을 그대로 쓰므로 여기에 없다.

| 그룹 | 핀 | AF | 이유 |
|---|---|---|---|
| `usart3_pins_sc6` | PD8 TX / PD9 RX | AF7 | 벤더 그룹은 PB10을 쓰는데 우리 보드에서 PB10은 다른 용도 |
| `uart5_pins_sc6` | PB13 TX / PB12 RX | AF14 | 벤더는 PB6/PB5 — 우리 보드에선 I2C1·LCD 리셋 자리 |
| `pwm1_ch2_pins_sc6` | PE11 | AF1 | 벤더 그룹이 PE9/PE11/PE14를 묶는데 PE14는 테스트 포인트 |
| `pwm2_ch1_pins_sc6` | PA15 | AF1 | 벤더는 이 핀을 CEC로 씀 |
| `pwm8_ch4_pins_sc6` | PI2 | AF3 | 벤더에 없는 그룹 (외부 워치독) |
| `i2c6_pins_sc6` | PZ6 / PZ7 | AF2 | 벤더에 I2C6 그룹 자체가 없음 |

각 그룹에는 짝이 되는 `*_sleep_pins_sc6`(ANALOG)도 같이 있다. I2C6만 `&pinctrl_z` 아래에 있는데, GPIOZ가 별도 핀 컨트롤러이기 때문이다.

### 1-3. stm32mp157a-sc6-v1.dts — 신규

구조는 이렇다.

```c
#include "stm32mp157c-ya157c-v2.dts"        /* 벤더 보드 DTS 전체를 가져오고 */
#include "stm32mp157-sc6-pinctrl.dtsi"      /* 우리 핀 그룹을 더한 다음 */
#include <dt-bindings/pwm/pwm.h>
                                            /* 아래에서 다른 것만 덮어쓴다 */
```

바꾼 내용을 종류별로 나눴다.

#### 지운 노드

| 대상 | 이유 |
|---|---|
| `/delete-node/ &panel_backlight;` | PB8을 GPIO로 잡는데, 우리 보드에서 PB8은 C_AC_ON(PWM 출력) |
| `/delete-node/ joystick;` | PI11, 우리 보드에 없음 |
| `/delete-node/ led;` | 벤더 LED 정의를 지우고 아래 `leds`로 다시 정의 |

#### 새로 만든 노드 (루트)

| 노드 | 내용 |
|---|---|
| `model` / `compatible` | `"KNV SC6_0 (MYC-YA157C-V2)"`, `"knv,stm32mp157a-sc6"` |
| `aliases` | serial0=uart4(콘솔), 1=usart3, 2=uart8, 3=uart5, 4=uart7 |
| `leds` | bled(PA14, heartbeat), rled(PA13), dout1~4(PG10/PG12/PI9/PI1) |
| `din-keys` | din1(PH13), din2(PH6), b_ac_in(PH4), c_ac_in(PH5) — 인터럽트, 양쪽 에지 |
| `int-keys` | pm_int(PH12), em_int(PH14), rcd_int(PH15) — 인터럽트, 양쪽 에지 |

`din-keys`의 DIN1/DIN2는 **핀리스트와 반대로** 적었다. 핀리스트가 틀렸고 회로도가 맞다는 것을 설계자에게 확인받았다.

`int-keys`는 처음에는 없었다. 이 세 핀을 "아무 노드도 붙이지 않은 입력"으로 두었더니 U-Boot이 남긴 LCD 출력 설정이 그대로 살아남아 반대편 출력과 맞붙었다. 인터럽트를 붙이면 커널이 부팅 중에 핀을 입력으로 확정해준다. (자세한 경위는 [9/21 글](#))

#### 켠 것 / 핀을 바꾼 것

| 대상 | 변경 |
|---|---|
| `&usart3` | 우리 핀 그룹, DMA 제거, `okay` |
| `&uart5` | 핀을 PB13/PB12로 교체 (전력량계) |
| `&i2c6` | 우리 핀 그룹, 400kHz, `okay` (ATECC608B 보안 칩) |
| `&spi1` | `okay`, CS = PZ3 |
| `&spi1` 아래 `ethernet@0` | **QCA7005** — `qca,qca7000`, 인터럽트 PG7 상승 에지, mode 3, 8MHz |
| `&gpioc` 아래 `qca_reset_hog` | PC3(Q_RST)을 HIGH로 고정 — QCA7005 리셋 해제 |
| `&timers1` / `pwm` | PE11 (B_AC_ON) |
| `&timers2` / `pwm` | PA15 (PWM_CP) |
| `&timers4` / `pwm` | PB8 (C_AC_ON) |
| `&timers8` / `pwm` | PI2 (PWM_WDI, 외부 워치독) |
| `&adc` | `vref-supply = <&vrefbuf>` (2.5V), 채널 0·1, 샘플 시간 10µs, adc2 끔 |
| `&gpioh` | `gpio-line-names` — PM_INT, DIN1, EM_INT 등 이름만 붙임 |

ADC 기준전압이 가장 중요한 변경이었다. 벤더 설정은 기준전압을 3.3V 레귤레이터로 물려두고 있었는데, 우리 보드는 내부 2.5V 레퍼런스를 쓴다. 틀렸다면 에러 없이 CP 전압 판정이 32% 어긋났을 것이다.

#### 끈 것

| 대상 | 이유 |
|---|---|
| `&i2c2` (+ `touchscreen@38` 삭제) | PH4/PH5가 우리 보드에선 AC 검출 입력 |
| `&m4_spi1` | 벤더가 SPI1을 M4 코어에 넘겨둠. 리눅스가 쓰려면 꺼야 함 |
| `&cec` | PA15를 잡음 — 우리는 PWM_CP |
| `&dsi` / `&ltdc` / `&gpu` | 디스플레이 없음 |
| `&m_can1` | 배선과 트랜시버가 아예 없음 |

## 2. 커널 설정 (.config)

바꾸기 전 설정을 백업해 두었기 때문에 정확히 비교할 수 있었다.

```diff
- # CONFIG_QCA7000_SPI is not set
+ CONFIG_QCA7000=m
+ CONFIG_QCA7000_SPI=m
```

QCA7005 드라이버를 모듈로 켠 것뿐이다. SPI 컨트롤러 드라이버(`SPI_STM32`)가 이미 모듈이라 같은 방식으로 맞췄다.

**커널 이미지(`uImage`)는 다시 빌드하지 않았다.** 이 설정으로 모듈 2개(`qcaspi.ko`, `qca_7k_common.ko`)만 빌드해서 보드에 넣었고, 커널 버전(5.4.31)이 같아서 벤더 커널에 그대로 올라간다.

## 3. U-Boot

### 3-1. -u-boot.dtsi — 31줄 추가

U-Boot 소스는 git 저장소라 diff로 정확히 볼 수 있다. 추가한 건 이게 전부다.

```diff
--- a/arch/arm/dts/stm32mp157c-ya157c-512d-v2-u-boot.dtsi
+++ b/arch/arm/dts/stm32mp157c-ya157c-512d-v2-u-boot.dtsi
@@ -188,3 +188,34 @@
 	dr_mode = "peripheral";
 };

+/* (왜 끄는지 설명하는 주석 블록) */
+&panel_rgb {
+	status = "disabled";
+};
+
+&panel_backlight {
+	status = "disabled";
+};
+
+&ltdc {
+	status = "disabled";
+};
```

| 노드 | 하던 일 | 끈 이유 |
|---|---|---|
| `panel_rgb` | LCD 핀(`ltdc_pins_a`)을 출력으로 설정 | PH12/14/15를 실제로 드라이브한 주범 |
| `panel_backlight` | PB8을 HIGH로 출력 | PB8은 C_AC_ON |
| `ltdc` | LCD 컨트롤러 | 환경변수와 무관하게 강제로 일찍 켜지게 돼 있음 |

`ltdc`만 끄면 안 됐다. 벤더 DTS에서 `ltdc`의 핀 설정은 주석 처리돼 있고, 핀을 실제로 잡는 건 `panel_rgb`였기 때문이다. (자세한 경위는 [9/23 글](#))

### 3-2. U-Boot 설정 (.config)

새로 만든 기본 설정(`stm32mp15_trusted_defconfig`)과 실제 빌드에 쓴 설정을 비교했다.

```diff
- # CONFIG_FIT_SIGNATURE is not set
+ CONFIG_FIT_SIGNATURE=y
+ CONFIG_FIT_SIGNATURE_MAX_SIZE=0x10000000
+ # CONFIG_FIT_ENABLE_RSASSA_PSS_SUPPORT is not set
...
- # CONFIG_RSA is not set
+ CONFIG_RSA=y
+ # CONFIG_SPL_RSA is not set
+ CONFIG_RSA_SOFTWARE_EXP=y
```

손으로 바꾼 건 `CONFIG_FIT_SIGNATURE=y` 하나다. 나머지는 `olddefconfig`가 의존 관계를 따라 자동으로 채운 것이다.

이건 기능이 필요해서가 아니라 **빌드 실패를 피하려고** 바꿨다. 이 버전의 `mkimage` 소스는 서명 함수를 조건 없이 호출하는데, 그 함수의 정의는 이 옵션이 켜져 있을 때만 컴파일된다.

**주의**: `stm32mp15_trusted_defconfig`를 다시 실행하면 이 설정이 날아간다.

### 3-3. git이 "수정됨"으로 보여주지만 우리가 고치지 않은 것

U-Boot 소스를 Windows에서 받아 WSL로 복사했더니, `git status`에서 **거의 모든 파일이 수정됨**으로 나왔다. 실제 내용 변경이 아니라 복사 과정에서 생긴 차이였다.

| 보이는 차이 | 원인 |
|---|---|
| 모든 파일이 수정됨 | 파일 권한(실행 비트)이 바뀜 |
| `LICENSE` 등 수백 줄 변경 | 줄바꿈이 CRLF로 바뀜 |
| `dt-bindings` 등 심볼릭 링크 삭제 | Windows에서 압축을 풀면서 링크가 빠진 것으로 보임 |
| `Makefile.sdk` 삭제 | 벤더 패키지에서 이 파일이 소스 폴더 바깥에 들어 있었음 |

권한과 줄바꿈 차이를 빼고 보는 옵션으로 걸러내야 진짜 수정 내역만 남는다(6절).

## 4. 보드에서 바뀐 것

| 위치 | 내용 | 언제 |
|---|---|---|
| `/boot/stm32mp157a-sc6-v1.dtb` | 우리 DTB (현재 72,062바이트) | 9/15~ |
| `/boot/mmc0_extlinux/stm32mp157c-ya157c-v2_extlinux.conf` | `LABEL sc6` 추가, `DEFAULT sc6` | 9/15 |
| `/lib/modules/5.4.31/kernel/drivers/net/ethernet/qualcomm/` | `qcaspi.ko`, `qca_7k_common.ko` + `depmod` | 9/16 |
| SD카드 `/dev/mmcblk1p3` (SSBL) | 새 `u-boot.stm32` | 9/23 |
| `/home/root/ssbl-sd-original-backup.bin` | 원래 SSBL 백업 | 9/23 |
| `/usr/local/bin/` | open-plc-utils 109개 (plctool, plcboot 등) | 10/14 |
| `/lib/firmware/qca7005/` | QCA7005 펌웨어(`.nvm`), EVSE PIB(`.pib`) | 10/14 |
| `/usr/local/sbin/qca7005-fwload.sh` | 펌웨어 적재 스크립트 | 10/14 |
| `/etc/systemd/system/qca7005-fw.service` | 부팅 시 자동 적재 (enable) | 10/14 |

부팅 메뉴는 벤더 항목 3개를 지우지 않고 그대로 두었다. 우리 DTB에 문제가 생기면 부팅 메뉴에서 벤더 항목을 골라 바로 되돌아갈 수 있다.

```text
DEFAULT sc6
LABEL sc6
        KERNEL /uImage
        FDT /stm32mp157a-sc6-v1.dtb
        ...
LABEL stm32mp157c-ya157c-v2          ← 원본 유지
LABEL stm32mp157c-ya157c-hdmi-v2     ← 원본 유지
LABEL stm32mp157c-ya157c-lcd-v2      ← 원본 유지
```

수정한 파일이 `extlinux.conf`가 아니라 **보드 이름이 붙은 파일**이라는 점도 적어둔다. U-Boot은 보드 이름이 붙은 파일을 먼저 읽는다. 처음에 `extlinux.conf`를 고쳤다가 아무 변화가 없어서 한참 헤맸다.

**eMMC는 한 번도 건드리지 않았다.** 모든 변경은 SD카드에만 있다.

## 5. 빌드 환경 (WSL, ~/work)

소스 수정은 아니지만, 같은 결과를 다시 만들려면 필요한 것들이다.

| 파일 | 용도 | 핵심 |
|---|---|---|
| `kbuild.sh` | 커널 DTB·모듈 | SDK를 불러온 뒤 PATH를 시스템 우선으로 되돌림 |
| `ubuild.sh` | U-Boot | 위에 더해 `KCFLAGS`, `PKG_CONFIG_SYSROOT_DIR` 등 해제 |
| `plcbuild.sh` | open-plc-utils | `CROSS`와 `CC="$CC"`를 같이 넘김 |
| `qca7005-fw/pack.sh` | 보드 설치 묶음 | 디렉터리 항목 없이 파일만 묶음 |

## 6. 이 목록을 어떻게 확인했나

6주치 작업을 기억으로 정리하면 빠지는 게 생긴다. 그래서 종류별로 다른 방법을 썼다.

**커널 소스 — 수정 날짜로 찾기**

커널 소스는 git 저장소가 아니라 벤더 압축 파일을 푼 것이다. 압축을 풀 때 파일 날짜가 원래 날짜(2021년)로 유지되므로, 올해 바뀐 파일만 찾으면 우리가 건드린 파일이다.

```console
$ find ~/work/myir-st-linux -newermt 2026-01-01 -type f
.../arch/arm/boot/dts/stm32mp157-sc6-pinctrl.dtsi
.../arch/arm/boot/dts/Makefile
.../arch/arm/boot/dts/stm32mp157a-sc6-v1.dts
```

세 개뿐이었다. 벤더 원본 DTS를 하나도 고치지 않았다는 게 여기서 확인된다.

**커널 설정 — 백업과 비교**

```console
$ diff build/.config.bak-20260908-143849 build/.config
```

**U-Boot 소스 — git diff에서 잡음 걸러내기**

```console
$ git -c core.fileMode=false diff --ignore-cr-at-eol --stat
```

`core.fileMode=false`는 권한 차이를, `--ignore-cr-at-eol`은 줄바꿈 차이를 무시한다. 이렇게 거르면 실제로 바뀐 DTS 파일 하나(+31줄)가 드러난다.

**U-Boot 설정 — 새 기본 설정과 비교**

```console
$ make O=/tmp/ub-def stm32mp15_trusted_defconfig
$ diff /tmp/ub-def/.config build-trusted/.config
```

기본 설정을 임시 폴더에 새로 만들어서 비교했다. 작업 중인 빌드 폴더를 건드리지 않는다.

## 7. 정리하다 발견한 것

목록을 만들려고 DTS를 처음부터 다시 읽으면서, **주석 몇 군데가 지금 상태와 맞지 않는 것**을 발견했다. 코드는 맞는데 주석이 예전 상태에 머물러 있다.

| 위치 | 주석 내용 | 실제 |
|---|---|---|
| 파일 머리 "남은 확인 사항" | Q_RST 극성, SPI 모드, VREFBUF 확인 필요 | 셋 다 확인 완료 |
| `panel_backlight` 삭제 부분 | "대체 노드(pwm-backlight)는 아래에 있다" | LCD를 빼면서 그 노드도 지웠다 |
| `qca_reset_hog` | "극성 확인 필요" | QCA7005가 응답하므로 HIGH가 맞음 |
| 미배정 핀 목록 | "PC3 Q_RST — 칩이 정해지면 reset-gpios로" | 이미 hog로 사용 중 |

DTS 주석에 근거를 남기자고 해놓고 주석을 갱신하지 않으면, 나중에 읽는 사람(아마 나)이 틀린 근거를 믿게 된다. 다음 DTS 수정 때 같이 정리할 항목으로 남긴다.

## 마치며

| 영역 | 수정 규모 |
|---|---|
| 커널 소스 | 신규 2개 + Makefile 1줄 |
| 커널 설정 | 2항목 |
| U-Boot 소스 | 1개 파일에 31줄 |
| U-Boot 설정 | 1항목 |
| 벤더 원본 파일 | **0개** |

6주 동안 꽤 많은 일을 했다고 생각했는데, 실제로 바뀐 소스는 이 정도다. 대부분의 시간은 **무엇을 바꿔야 하는지 알아내는 데** 들었다. 회로도, 커널 소스, 실측을 대조하는 일이었다.

벤더 파일을 직접 고치지 않고 덮어쓰는 방식을 지킨 덕분에, 목록이 짧고 되돌리기도 쉽다. 새 파일을 지우고 Makefile 한 줄을 빼면 커널 소스는 원래대로 돌아간다.
